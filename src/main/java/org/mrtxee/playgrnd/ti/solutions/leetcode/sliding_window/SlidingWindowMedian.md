Вот ваш код с комментариями **над каждой строкой**, поясняющими действие и причину:

```java
public class Solution {
    public double[] medianSlidingWindow(int[] nums, int k) {
        // Создаём динамический список для последовательного сохранения найденных медиан
        List<Double> resList = new ArrayList<>();
        // Запоминаем длину массива, чтобы контролировать границы цикла сдвига окна
        int n = nums.length;
        // Левый указатель: индекс элемента, который покинет окно при сдвиге вправо
        int i = 0;
        // Правый указатель: индекс нового элемента, который войдёт в окно
        int j = k - 1;
        // Список для хранения элементов текущего окна в строго отсортированном порядке
        List<Integer> temp = new ArrayList<>();
        // Загружаем первые k-1 элементов окна (последний добавим внутри цикла для удобства сдвига)
        for (int x = 0; x < k - 1; x++) {
            temp.add(nums[x]);
        }
        // Сортируем начальные элементы, чтобы сразу получить упорядоченную структуру для поиска медианы
        Collections.sort(temp);
        // Цикл выполняется, пока правый указатель не выйдет за пределы массива
        while (j < n) {
            // Захватываем новый элемент, входящий в окно справа
            int num = nums[j];
            // Ищем позицию для вставки нового элемента через бинарный поиск (работает только с отсортированным списком)
            int insertIdx = Collections.binarySearch(temp, num);
            // Если элемента нет в списке, binarySearch возвращает (-(точка вставки) - 1)
            if (insertIdx < 0) {
                // Преобразуем код возврата в реальный индекс, куда нужно вставить элемент для сохранения сортировки
                insertIdx = -insertIdx - 1;
            }
            // Вставляем элемент по найденному индексу: ArrayList автоматически сдвигает элементы вправо
            temp.add(insertIdx, num);

            // Вычисляем медиану текущего окна в зависимости от чётности k
            if (k % 2 == 1) {
                // При нечётном k медиана — ровно центральный элемент
                double median = (double) temp.get(k / 2);
                resList.add(median);
            } else {
                // При чётном k медиана — среднее арифметическое двух центральных элементов
                int idx = k / 2;
                double median1 = (double) temp.get(idx);
                double median2 = (double) temp.get(idx - 1);
                resList.add((median1 + median2) / 2);
            }

            // Ищем индекс элемента, который должен покинуть окно слева (старый элемент nums[i])
            int removeIdx = Collections.binarySearch(temp, nums[i]);
            // Страховка на случай, если элемент не найден (теоретически невозможно при корректном вводе)
            if (removeIdx < 0) {
                removeIdx = -removeIdx - 1;
            }
            // Удаляем элемент по индексу: ArrayList сдвигает все последующие элементы влево, закрывая дыру
            temp.remove(removeIdx);

            // Сдвигаем окно на одну позицию вправо: левый указатель++, правый указатель++
            i++;
            j++;
        }

        // Создаём примитивный массив double нужного размера для возврата результата
        double[] resArray = new double[resList.size()];
        // Копируем элементы из List в примитивный массив (Java не позволяет привести List<Double> в double[] напрямую)
        for (int x = 0; x < resList.size(); x++) {
            resArray[x] = resList.get(x);
        }

        // Возвращаем итоговый массив медиан для каждого положения окна
        return resArray;
    }
}
```

---

### 🎯 Цель алгоритма
Для каждого положения скользящего окна размера `k` в массиве `nums` найти **медиану** (среднее значение в отсортированном подмножестве) и вернуть массив этих медиан.  
Алгоритм поддерживает текущее окно **всегда отсортированным**, что позволяет получать медиану за `O(1)` просто обращением к центру списка.

---

### 📊 Сложность

| Тип | Сложность | Объяснение |
|-----|-----------|------------|
| **Временная** | **O(n × k)** | Цикл выполняется `n - k + 1` раз. Внутри каждой итерации: бинарный поиск `O(log k)`, но `add(index, val)` и `remove(index)` в `ArrayList` требуют сдвига элементов → `O(k)`. Итого: `O(n × k)`. |
| **Пространственная** | **O(n)** | Список `temp` хранит `k` элементов → `O(k)`. Список результатов `resList` хранит до `n` медиан → `O(n)`. В сумме доминирует `O(n)`. |

> 💡 **Важное замечание**: Это рабочее решение, но **не оптимальное** по времени. В продакшене или на собеседовании ожидаемый ответ — `O(n log k)` с использованием двух куч (`PriorityQueue`) или `TreeMap`, где удаление/вставка не требуют линейного сдвига элементов. Ваш подход выигрывает в простоте реализации, но проигрывает на больших `k`.
