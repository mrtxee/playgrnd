Вот оптимальное решение с комментариями **над каждой строкой**, поясняющими действие и причину:

```java
public int characterReplacement(String s, int k) {
  // Частотный массив для 26 заглавных латинских букв (0 = 'A', 1 = 'B' ...)
  int[] freq = new int[26];
  // Левый указатель скользящего окна
  int left = 0;
  // Хранит максимальную частоту ОДНОГО символа внутри текущего окна
  int maxFreq = 0;
  // Хранит длину самой длинной валидной подстроки, найденной на данный момент
  int maxLen = 0;

  // Правый указатель последовательно расширяет окно до конца строки
  for (int right = 0; right < s.length(); right++) {
    // Преобразуем символ в индекс 0-25 и увеличиваем его счётчик в текущем окне
    int charIndex = s.charAt(right) - 'A';
    freq[charIndex]++;
    // Обновляем макс. частоту: нам важен только самый частый символ в окне
    maxFreq = Math.max(maxFreq, freq[charIndex]);

    // Проверяем, превышает ли необходимое количество замен лимит k:
    // (right - left + 1) — текущая длина окна
    // maxFreq — количество символов, которые УЖЕ совпадают (их менять не надо)
    // Разница = количество замен, нужных для превращения окна в однобуквенное
    if ((right - left + 1) - maxFreq > k) {
      // Замен не хватает: "сжимаем" окно слева, убирая символ из учёта
      freq[s.charAt(left) - 'A']--;
      // Сдвигаем левую границу вправо на 1 позицию
      left++;
    }

    // Обновляем глобальный максимум длины валидного окна
    // (Фактически окно либо растёт, либо сохраняет свой рекордный размер)
    maxLen = Math.max(maxLen, right - left + 1);
  }

  // Возвращаем длину самой длинной подстроки, которую можно сделать однородной за ≤ k замен
  return maxLen;
}
```

---

### 🎯 Цель и ключевая идея
Найти максимальную длину подстроки, которую можно превратить в строку из **одинаковых символов**, заменив не более `k` символов.  
Алгоритм использует **скользящее окно** и частотный массив. Вместо перебора всех подстрок, мы расширяем окно и проверяем простое математическое условие.

---

### 📐 Математика условия валидности окна
```
необходимые_замены = длина_окна - частота_самого_популярного_символа
```
Если `необходимые_замены ≤ k`, окно валидно.  
**Пример:** `s = "ABAB", k = 2`, окно `"[ABAB]"` → длина 4, макс. частота (`A` или `B`) = 2.  
`4 - 2 = 2 ≤ k` → валидно. Ответ: 4.

---

### 💡 Важный нюанс оптимизации (почему `maxFreq` не уменьшается при сдвиге `left`?)
Когда окно сжимается слева, счётчик уходящего символа уменьшается, но `maxFreq` **никогда не декрементируется**. Это не ошибка, а хитрая оптимизация:
- Нам нужно найти **максимальную длину** когда-либо достигнутого валидного окна.
- Если `maxFreq` стал меньше, условие `(right - left + 1) - maxFreq > k` просто не позволит окну вырасти дальше, пока мы не найдём новый символ с большей частотой.
- Это избавляет от поиска `max` по всему массиву `freq` на каждой итерации, сохраняя `O(n)` вместо `O(26n)`.

### 📊 Сложность
| Тип | Сложность | Объяснение |
|-----|-----------|------------|
| **Временная** | **O(n)** | `right` проходит строку ровно 1 раз. Все операции внутри цикла (`Math.max`, доступ к массиву, инкременты) выполняются за `O(1)`. |
| **Пространственная** | **O(1)** | Массив `freq` имеет фиксированный размер 26 (не зависит от `n`). Доп. переменные занимают константную память. |
