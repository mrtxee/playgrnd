⚠️ **Важное уточнение**: вы смешали два разных алгоритма.
- `MergeSort` → **сортировка слиянием** (делит массив пополам, затем сливает отсортированные части).
- `InsertionSort` → **сортировка вставками** (берёт элемент и вставляет его в правильную позицию в уже отсортированной части).

Ниже приведено **самое простое и читаемое решение именно для MergeSort** (как указано в вашем запросе), с комментариями **над каждой строкой**.

```java
public static void mergeSort(int[] arr) {
  // Базовый случай рекурсии: массив из 0 или 1 элемента уже отсортирован
  if (arr == null || arr.length <= 1) return;
  // Создаём вспомогательный массив один раз, чтобы не пересоздавать его на каждом шаге рекурсии
  int[] temp = new int[arr.length];
  // Запускаем рекурсивную сортировку для всего диапазона индексов [0, length-1]
  sort(arr, temp, 0, arr.length - 1);
}

private static void sort(int[] arr, int[] temp, int left, int right) {
  // Если левая граница >= правой, подмассив пуст или содержит 1 элемент → сортировать нечего
  if (left >= right) return;
  // Находим середину текущего подмассива, безопасно избегая переполнения при (left + right)
  int mid = left + (right - left) / 2;
  // Рекурсивно делим и сортируем левую половину массива
  sort(arr, temp, left, mid);
  // Рекурсивно делим и сортируем правую половину массива
  sort(arr, temp, mid + 1, right);
  // Сливаем две уже отсортированные половины в один упорядоченный подмассив
  merge(arr, temp, left, mid, right);
}

private static void merge(int[] arr, int[] temp, int left, int mid, int right) {
  // Копируем текущий рабочий диапазон во вспомогательный массив, чтобы не перезаписать данные до слияния
  for (int i = left; i <= right; i++) temp[i] = arr[i];
  // Указатель на текущий элемент левой отсортированной половины
  int i = left;
  // Указатель на текущий элемент правой отсортированной половины
  int j = mid + 1;
  // Указатель на позицию записи результата в исходный массив
  int k = left;
  // Пока оба указателя не вышли за границы своих половин, сравниваем и записываем меньший
  while (i <= mid && j <= right) {
    // Если элемент из левой половины меньше или равен, записываем его и двигаем оба указателя
    if (temp[i] <= temp[j]) arr[k++] = temp[i++];
    // Иначе записываем элемент из правой половины (он меньше)
    else arr[k++] = temp[j++];
  }
  // Если в левой половине остались элементы, дописываем их в конец (правая уже закончилась)
  while (i <= mid) arr[k++] = temp[i++];
  // Если в правой остались элементы, дописываем их (нужен для корректности, хотя часто не срабатывает)
  while (j <= right) arr[k++] = temp[j++];
}
```

---

### 🎯 Цель алгоритма
Отсортировать массив **по возрастанию**, используя стратегию **«разделяй и властвуй»**:
1. Рекурсивно разбиваем массив на две половины, пока размер подмассивов не станет `1`.
2. Последовательно **сливаем** соседние отсортированные подмассивы, сравнивая их элементы и формируя новую упорядоченную последовательность.
3. Гарантируем **стабильность сортировки** (равные элементы сохраняют исходный порядок) и предсказуемую производительность на любых данных.

### 📊 Сложность

| Тип | Сложность | Объяснение |
|-----|-----------|------------|
| **Временная** | **O(n log n)** | Массив делится пополам `log n` раз. На каждом уровне рекурсии происходит один полный проход слияния за `O(n)`. Итого: `O(n) × O(log n) = O(n log n)`. Работает стабильно даже в худшем случае. |
| **Пространственная** | **O(n)** | Требуется дополнительный массив `temp` того же размера, что и исходный, для безопасного слияния. Рекурсивный стек добавляет `O(log n)`, но доминирует линейная память. |

> 💡 **Почему это оптимально?**  
> MergeSort не зависит от исходного порядка данных (в отличие от QuickSort, который может скатиться до O(n²)). Он идеально подходит для сортировки больших массивов, связанных списков и внешних данных, где важна стабильность и гарантия времени выполнения.
